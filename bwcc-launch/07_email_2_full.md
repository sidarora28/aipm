Fair question. Here's the inside of week 2.

**The exercise:**
You bring one feature you speced this quarter — anything from your real backlog. Doesn't matter if it's small. The smaller and more real, the better.

**What you do in the live session:**

1. We open Claude Code together. You point it at a repo (yours if you can, a sandbox we provide if you can't).
2. You paste your PRD in. As-is, no cleanup.
3. We watch what Claude does with it. Where does it ask for more? Where does it guess? Where does it nail it?
4. You rewrite the PRD in real time, based on what you just learned about what a model needs to ship a feature.
5. By the end of the session, you have a working prototype of that feature.

That last bullet is the part most people don't believe until they're in it. PMs who have never written code finish week 2 with something they can put in front of a user the next morning.

**What cohort 0 actually shipped in week 2:**
- A self-serve onboarding flow that previously had a 3-week eng estimate
- An internal admin tool for support that had been "next quarter" for 6 months
- A feature flag dashboard that one PM had been mocking up in Figma for a year

None of those people wrote a line of code by hand.

**The rest of the cohort:**
- Week 1: workflow setup, prompt patterns, when to use Claude Code vs. plain chat
- Week 3: shipping the prototype to a real user, capturing what you learn
- Week 4: scaling the workflow into how you do PM work week-to-week — research, synthesis, roadmap drafts, comp teardowns
